VISUAL GUIDE · APPLIED TO THE PAPER'S NETWORK

How to make a Benders cut stronger

See why the usual coefficients can be too generous — by closing one arc at a time and watching the shortest path change.

The idea in one minute

1. Pick a path

Start with a shortest path in the original network.

2. Close a road

Measure how much longer the best surviving route becomes.

3. Tighten the cut

Allow only the necessary increase instead of a needlessly large coefficient.

We use the same five-node graph and arc lengths as the big-M guide. Root 2 wants to reach destination 3. The interdiction budget is 1, with the paper's original arc interdiction costs; this means at most one cost-1 arc can be closed.

1What is the path before interdiction?

The blue route has total length 5. A Benders cut starts from this perfectly concrete path. Its job is to bound how much worse the follower can do after interdiction.

2What happens if road 2 → 5 is closed?

The old route disappears. The follower finds a detour of length 10. Compared with the original 5, this is an increase of 5.

So this arc only needs a cut coefficient of 5 in the budget-one example.

3What if road 5 → 3 is closed instead?

This time the shortest distance becomes 9, an increase of just 4. The two arcs affect the same selected path, but their real consequences are different.

4Try the three scenarios yourself

The other budget-feasible cost-1 arcs are not on this selected path, so leaving both selected arcs open preserves the length-5 route.

5Now read the strengthened cut

Start at 5. Closing arc 2→5 allows at most +5; closing arc 5→3 allows at most +4. We do not need to pay the full generic big-M penalty in this cut.

θ₂ ≤ 5 + 5x₂₅ + 4x₅₃
Why stronger? In a maximization master, a smaller correct right-hand side restricts overoptimistic values of θ₂. The standard Benders coefficients are M(a,2) multiplied by the selected flow; whenever these are larger than 5 or 4, the new cut is tighter.

Important limitation: we used budget 1. With budget 2, interdictions can reinforce each other: adding separately computed increases can be wrong. The v2 appendix proves the condition for valid cut coefficients over every feasible interdiction set and provides safe tree-based coefficients.
